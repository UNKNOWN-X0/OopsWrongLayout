# Design System: Oops/Wrong Layout

## Overview

**Creative North Star: "The Telegraph Code Book, Typed Out"**

Conversion here is a fixed code table, so the interface is drawn as one: a ruled sheet of paper where every physical key is a cell carrying its source character top-left and its target character bottom-right, and the result is struck into the second pane like a typewriter. The mechanism is visible at all times. The user sees which keys their text used, how often, and what each became, which is why the conversion reads as mechanical rather than guessed. The logo is the same idea at 30px: one keycap with a Latin A top-left and a Thai ก bottom-right.

The material is flat stationery: a tinted ground, a lighter sheet, keycaps one step tonally apart, and 1px ink rules that do all the structural work. There is no texture, no gradient, and no resting shadow. The user picks the stationery: five papers (Parchment, Carbon Copy, Ledger Green, Blueprint, Kraft), each printed in a light and a dark mode. One saturated ink per paper and mode (ink-blue on Parchment light) is held back for the things that are live: struck and used keys, the caret, the primary Copy action, focus, the chosen option. Everything else is the paper's ink and its faded variant.

Density is that of a working tool: one header rule, a heading over a single line of intro, a row of controls, the two-pane frame, a single mono status line, then the full-width code table, two short notes and a one-line credit. Type splits by job: Public Sans speaks the interface, Martian Mono carries anything that is a code, count, label or typed character, and Noto Sans Thai, JP and Hebrew carry the scripts the code table maps into.

**Key Characteristics:**
- Flat ruled stationery; 1px rules in strong ink outline the frames, light rules divide inside them.
- One accent per paper and mode, reserved for live state and the single primary action.
- Mono for codes, counts, labels and typed text; sans for interface prose.
- The code table is the signature: legend top-left, result bottom-right, heat tint from the accent. The keycap logo repeats it.
- Motion is mechanical and short: a key strike, a typed-out result, a paper slip, legends rolling like a split-flap board.
- Five papers × two modes from one token set; Mode = System follows the OS.

## Colors

Ten paper-and-ink palettes share one set of roles (ground, sheet, keycap, ink, muted ink, rule, strong rule, accent, ink-on-accent, warning, plus the ink as an RGB triple for shadows). Two independent settings choose among them, both written to the root element: `data-paper` (parchment, carbon, ledger, blueprint, kraft) picks the colouring and `data-scheme` (light, dark) picks the mode, resolved from Mode = System, Light or Dark. With no attributes at all (scripts blocked) the page is Parchment light. Parchment light is the default and the role names below use it; dark tokens carry `-dark-` in their key.

### Primary
- **Ink-Blue** (`ink-blue`): the one live colour. Fills the most-used key and tints every used key in proportion; draws the caret, the focus ring, text selection, the slash in the wordmark and the ก in the logo, the lead count in the status line, the check on the chosen paper and the chosen layout option, the Auto-detect flash ring and the Copy button. Each paper carries its own: **Carbon Violet** (Carbon Copy), **Ledger Green** (Ledger Green), **Blueprint Blue** (Blueprint), **Kraft Teal** (Kraft). The dark mode lifts each to a lighter ink (**Pale Ink-Blue**, **Pale Violet**, **Jade**, **Stamp Teal**), except Blueprint dark, which switches to **Pencil Yellow** on drafting blue.
- **Ink-Blue On** (`ink-blue-on`): text and icons laid on the accent: white in every light mode, the paper's own ground in every dark mode.

### Tertiary
- **Burnt Sienna** (`burnt-sienna`): the warning ink, used only for a non-zero "No match" or "Left as Latin" count in the status line. It is the same in all five light modes; dark modes lift it to **Amber**, and Blueprint dark to **Peach** so it stays apart from the yellow accent.

### Neutral
- **Parchment Ground** (`parchment-ground`): the page and html background, and the key top in the logo.
- **Parchment Sheet** (`parchment-sheet`): raised paper: the pane frame, the code table, the layout pickers and their listbox, buttons, the settings button and panel, and the Copied slip.
- **Parchment Keycap** (`parchment-keycap`): the resting fill of a key or kana cell, the hover fill for tabs, listbox options and paper rows, the fill of the chosen paper row, and the base the heat tint mixes into.
- **Sepia Ink** (`sepia-ink`): body text, typed text, target legends, the logo's base and its Latin A, and the fill of the active tab and every checked segment (with ground-coloured text on top).
- **Faded Sepia** (`faded-sepia`): secondary prose, labels, counts, source legends, placeholders, layout previews, paper notes, the mode icon, chevrons, the chart axes and the credit line.
- **Parchment Rule** (`parchment-rule`): inner dividers, picker, button and segmented borders, unused key borders, the code-table outline and the rules above the notes and the credit.
- **Parchment Rule Strong** (`parchment-rule-strong`): equal to the ink in every light mode; the header rule, the pane frame and its centre rule, the outline of the settings panel, the listbox and the slip, and hover borders. Dark modes soften it to a mid tone, and the logo's base takes it there in place of the ink.

Derived values (not separate tokens): **Accent Soft** is the heat ink mixed 14% into the keycap (the "Used" legend chip); the primary-button hover mixes the accent 88% with the ink; key heat mixes the heat ink into the keycap by the key's heat value in oklab. The heat ink is the accent everywhere except Blueprint dark, which sets `--heat-ink` to its pale ink (`blueprint-dark-heat-ink`) so used keys read as pencilled-in rather than yellowed; its most-used key still fills with Pencil Yellow.

### Named Rules
**The Live Ink Rule.** The accent marks only what is live or chosen: used and struck keys, the caret, focus, selection, the lead count, the chosen paper and layout, the Auto-detect flash, Copy. The two brand marks (the wordmark slash and the logo's ก) are the only static accent. Nothing else decorative is accent-coloured.

**The One Token Set Rule.** Every paper in every mode defines the same eleven role variables and nothing else changes between them; the one optional extra is `--heat-ink`. A new surface reads its colours from the roles, never from a paper's hex values. The only places hex values are written out are the paper swatches in the settings panel (which must preview papers other than the current one) and the static favicon; both must match the stylesheet.

## Typography

**UI Font:** Public Sans (with system-ui, sans-serif)
**Label/Mono Font:** Martian Mono (with ui-monospace, monospace)
**Script Fonts:** Noto Sans Thai, Noto Sans JP, Noto Sans Hebrew (the `--script` stack)

**Character:** A plain, legible grotesque for the interface set against a wide, slightly technical monospace that makes every character look like a code-book entry. The script faces appear wherever a character from another writing system has to sit beside Latin at the same weight.

### Hierarchy
- **Headline** (600, 22px, 1.2, -0.02em): the page title, set over the one-line intro.
- **Title** (600, 15px): the headings of the two notes at the foot of each page.
- **Body** (400, 15px, 1.5): interface prose, the intro line (max 100ch, muted), notes (max 68ch), picker values and options, buttons (500), status messages (14px).
- **Control** (Public Sans 500, 14px): the settings button, the Mode options and the paper names.
- **Caption** (Public Sans 400, 12px): paper notes ("Warm sheet, ink blue") and the code-table legend.
- **Wordmark** (Martian Mono 500, 15px, -0.02em): "Oops/Wrong Layout", with the slash in the accent, beside the keycap logo.
- **Typed** (Martian Mono with the script stack, 22px, 1.5, -0.01em; **Typed Compact** 19px at 720px and below): the text in both panes. Placeholders inside the output drop to 15px Public Sans.
- **Label** (Martian Mono 500, 11px, 0.06em, uppercase): field labels, pane heads ("A · Typed", "B · Fixed"), the code-table title, the "Mode" and "Paper" group heads, the Copied slip, chart axes.
- **Status** (Martian Mono 500, 12px, 0.04em, uppercase, tabular figures): the status line; its counts are set in ink, the lead count in the accent.
- **Preview** (Martian Mono with the script stack, 13px, 0.08em, muted): each layout's home-row keys (the characters on a s d f g) shown at the right of the picker and of every option, so a layout is recognised by its letters as well as its name.
- **Credit** (Martian Mono 500, 12px, 0.02em, muted, sentence case): the footer line "Made by Thanate Amornjiraporn (Focus)".
- **Cap source / Cap target** (Martian Mono 10–13px top-left; script stack 14–24px bottom-right, both scaling with cap width): the two legends on every key and kana cell.

### Named Rules
**The Code Is Mono Rule.** Anything the user could read as a code, a count or a typed character is set in Martian Mono with tabular figures where it counts; sentences are set in Public Sans.

**The Script Fallback Rule.** Any element that can show user text or a mapped character carries the `--script` stack after its primary face, so Thai, kana and Hebrew render in Noto at matching weight.

## Layout

A single centred column (max 1440px) with fluid side gutters (`spacing.gutter`, 16–56px) and 24px top / 40px bottom padding. The header is a full-bleed strip ruled underneath: logo and wordmark, tool tabs, and the Display settings button pushed right. Below it, in order: the title with its one-line intro underneath (4px apart), a wrapping row of controls aligned to their bottoms, the two-pane frame, the status line, the full-width code table, and the notes grid (auto-fit columns of at least 280px, 24px by 48px gaps, 40px above a light rule). A footer of the same 1440px width closes the page: a light rule, then the credit line (20px above, 32px below).

The two panes are equal columns inside one frame. The keyboard sizes its caps from the code table's own width (a container query): the widest row is 13.55 caps, so a cap is `(100cqw - 12 gaps) / 13.55`, clamped to 28–84px, with an 8px gap and rows two to four indented 0.55, 0.7 and 0.95 of a cap. The kana chart is a 17-column grid (an axis column plus 16 consonant groups) by 6 rows (axis plus 5 vowels), with dashed empty cells where the gojūon has no kana.

Floating surfaces anchor to their trigger: the settings panel (320px) hangs 8px below the settings button, right-aligned; a listbox takes its picker's width 6px below it, or opens upward when there is less than 300px below and more room above.

Responsive steps:
- **1100px and below:** the per-key usage count is hidden.
- **720px and below:** the header wraps and the tabs take a full-width row of equal halves; the panes stack with a horizontal rule between them; typed text drops to Typed Compact; control fields go full width; the kana chart tightens to 3px gaps and 40px cells showing only the kana, centred.
- **620px and below:** the keyboard splits into a left and a right half-board, stacked, with a dashed rule between them; caps are sized for 7.05 per row with a 5px gap and the left-half rows indented half a cap. The layout pickers stack with Swap and Auto-detect below, and the romaji Output switch stretches to full width.
- **480px and below:** the settings button drops the paper name and keeps the swatch, the mode icon and the chevron.

### Named Rules
**The Half-Board Rule.** On a phone the keyboard is never shrunk below legibility; it is cut at the hand split into two stacked half-boards, each row keeping its physical stagger.

## Elevation & Depth

The system is flat. Depth is carried by tone (ground, then sheet, then keycap) and by rules: strong ink rules for frames, light rules inside them. At rest nothing casts a shadow.

### Shadow Vocabulary
- **Panel overlay** (`box-shadow: 0 16px 40px rgb(var(--shadow) / 0.22)`): the Display settings panel. `--shadow` is each paper's ink as an RGB triple in light mode and black in every dark mode.
- **Listbox overlay** (`box-shadow: 0 16px 40px rgb(var(--shadow) / 0.2)`): an open layout picker's listbox, a touch lighter than the panel.
- **Strike ring** (transient, inside the 0.24s strike: `inset 0 2px 0 rgb(var(--shadow) / 0.2), 0 0 0 3px var(--accent)`): a key pressed down and ringed in the accent as its character is typed out, then released to nothing.
- **Flash ring** (transient, inside the 0.9s Auto-detect flash: `0 0 0 3px var(--accent)` with an accent border at its peak): both pickers after Auto-detect swaps the layouts.

### Named Rules
**The Flat Sheet Rule.** Resting surfaces never cast shadows; only the two floating surfaces do (the settings panel and an open listbox), and a key or picker only for the instant it is struck or flashed.

## Shapes

Gently softened rectangles throughout. Keys, cells, tabs, picker buttons, buttons, segmented options, listbox options and the paper swatch tiles use 6px (`rounded.sm`); the settings button, the segmented track and the paper rows 8px (`rounded.md`); the large framed sheets (pane frame, code table, listbox, settings panel) 10px (`rounded.lg`). The smallest marks go tighter: the 9px accent squares inside a paper swatch 2px (`rounded.mark`), the legend chips 3px, the Copied slip 4px. The settings-button swatch is the only circle: a 16px disc of the current ground, ringed in strong ink, with the accent as a dot in its centre.

A paper swatch is a 40×28 tile cut into two halves, light mode left and dark mode right, each half its ground with a small accent square centred on it, so every paper shows both of its modes before it is chosen.

Borders are always 1px. Swatch outlines use the ink triple at 30–35% so they read on any paper. The pane frame clips its children so the centre rule meets the outline cleanly. Dashed 1px rules mark absence or a cut: empty kana cells and the seam between the two half-boards.

The logo is a keycap drawn on a 32-unit grid: a 30×29 base (7 radius) in ink with a 26×23.5 key top (5.5 radius) in the ground set on it so a sliver of base shows below, and two filled legends taken as outlines from the project's own fonts (both OFL): a Latin A from Public Sans 800 in ink top-left, and a Thai ก (ko kai, no head loop, beak at top-left) from Noto Sans Thai 700 in the accent bottom-right. The legends are glyphs, not drawn strokes, so the mark speaks the same type as the interface. It sits inline at 30px in the header and ships as `icons/favicon.svg` (fixed Parchment colours, with Parchment-dark colours under `prefers-color-scheme: dark`) plus 32px, 180px and 512px PNGs.

Icons are inline SVG on a 24-unit grid with a round-capped 1.75 stroke in `currentColor`: a sprite of symbols defined once per page (chevron, swap, copy, check) and the three mode icons (monitor, sun, moon) written by the settings script. They show at 18px by default; 16px for the mode icon in the settings button and the listbox checks; 15px inside the Mode switch; 14px for chevrons in the pickers and the settings button.

## Components

### Buttons
Quiet paper buttons with one inked exception.
- **Shape:** 6px corners, 44px tall, 18px side padding; the icon-only Swap button is a 44px square.
- **Default:** sheet background, light rule border, ink text at 500.
- **Primary (Copy):** accent fill and border, ink-on-accent text at 600, with the copy icon. There is exactly one per page, anchored bottom-right inside pane B.
- **Hover / Active / Focus:** default buttons darken their border to the strong rule; primary darkens its fill toward the ink; all press down 1px; focus is a 2px accent outline offset 2px. Swap's arrows turn 180° on hover.
- **Disabled:** 45% opacity, not-allowed cursor; Copy stays disabled until there is a result.
- **Copied:** the copy icon is replaced by a check that draws itself in (0.4s), and turns back after 1.4s.

### Copied Slip
A small paper tag (label type, sheet fill, strong-rule outline, 4px corners) that rises out of the top of the Copy button like paper off the platen: clipped from the bottom, it unrolls, holds, and lifts away over 1.4s. A polite live region announces the copy (or the hand-copy fallback) for screen readers.

### Inputs / Fields
- **Layout picker:** a custom listbox button over the native select, which stays in the page hidden as the source of truth. The button: sheet background, light rule border, 6px corners, 44px tall, 12px side padding, the layout name in body text, its home-row preview in muted mono at the right, then a muted 14px chevron that turns over when open. Hover and open darken the border. Each field has a mono uppercase label above it.
- **Listbox:** sheet, strong-rule outline, 10px corners, 6px padding, listbox overlay shadow, at most 340px tall before it scrolls. Options are 6px rows (9px by 10px) with name, preview and a 16px accent check; the pointer or keyboard highlight fills an option with the keycap tone; the selected option is set at 600 and shows the check. Arrow keys, Home, End, Enter, Space, Escape, Tab and type-ahead work as in a native select.
- **Segmented switch (romaji Output, and Mode in the settings panel):** an 8px track with 3px inset holding 6px options; the checked option is filled with ink and set in ground colour; keyboard focus draws the accent ring around the option. Mode is a three-column version (System, Light, Dark) with an icon before each word in Control type.
- **Panes:** borderless textareas and a read-only output box set in the typed style with an accent caret. Focus is shown by turning the pane head's divider to the accent rather than outlining the field.

### Navigation
- **Logo and wordmark:** the 30px keycap logo, 10px gap, then the mono wordmark with its slash in the accent. On hover the logo's key top and both legends press down 1.5px, like a key under a finger.
- **Tool tabs:** text links with 6px corners and 8px by 14px padding; hover fills with the keycap tone; the current page is filled with ink and set in ground colour. At 720px they become a full-width row of equal halves.

### Display Settings
One button and one panel hold the two independent display choices.
- **Settings button:** sheet, light rule border, 8px corners, Control type: the circular swatch, the paper name, the current mode's icon in muted ink and a chevron that turns over when open. Hover darkens the border. Its accessible name states both choices ("Display settings: Parchment, System mode").
- **Panel:** a non-modal dialog, 320px, sheet, strong-rule outline, 10px corners, panel overlay shadow, 14px padding with 16px between two groups, each under a mono uppercase label. **Mode** is the three-way segmented switch. **Paper** is a list of five rows (8px corners, 8px by 10px, 12px gap): the two-mode swatch tile, the paper name in Control type over its note in Caption type, and an accent check at the right that scales in when chosen. Hover and the chosen row fill with the keycap tone; keyboard focus draws an inset 2px accent outline.
- **Behaviour:** the button announces a dialog and opening it moves focus to the checked Mode option; both groups are radio groups, so a choice applies at once; Escape closes the panel and returns focus to the button, and pointing or tabbing outside closes it. Both choices persist in local storage under `paper` and `mode` (absent means Parchment and System); the older single `theme` key is migrated once and removed. A script in each page's head applies them before first paint, and the page follows the OS while Mode is System and follows changes made in another tab.

### Pane Frame
Two equal halves of one ruled sheet: strong 1px outline, 10px corners, strong centre rule (a horizontal rule when stacked). Each half has a mono uppercase head with its letter and role on the left ("A · Typed", "B · Fixed"; "A · Romaji", "B · Kana") and a tabular character count on the right, over a light divider. The output holds at most 340px before it scrolls, with room left at the bottom for the Copy button.

### Status Line
A single mono uppercase line under the frame: the lead count in the accent ("Mapped", "Kana"), the miss count turning to the warning ink when it is not zero, then the plain count, with the rule of the conversion ("Same physical key → same character", "Hepburn spelling rules") pushed to the right. Empty or no-op states replace it with one sentence of sans body text.

### Code Table (signature)
The keyboard on Layout Fix and the gojūon kana chart on Romaji → Kana are the same component: a sheet panel (light rule, 10px corners) with a mono label title ("Key map · Thai → US English") and a three-chip legend (Unused, Used, Most used).
- **Cap:** keycap fill, light rule border, 6px corners, height 0.86 of its width (50px fixed in the chart). The source legend sits top-left in faded mono; the target legend bottom-right in the script stack. Thai combining marks are shown on a dotted circle (◌). From 1101px up, a tiny tabular count appears top-right on keys struck more than once.
- **Heat:** an unused key has heat 0; a used key gets 0.12 + 0.28 × (its count / the top count), so a used key never passes 0.4 and keeps full-ink legends; any key at the top count gets 1 and is "hot": solid accent fill, accent border and ink-on-accent legends. The tint comes from the heat ink (see Colors).
- **Strike:** as each character is typed out the key that produced it dips 2px and rings in the accent for 0.24s; a single typed character strikes just its key.
- **Roll:** when a layout changes, every cap's legends flip down into place like a split-flap board (0.5s each, 22ms apart in a wave across the keys).
- **Kana chart:** consonant columns × vowel rows with mono axis labels; each cell shows its romaji top-left and its kana bottom-right (kana only, centred, at 720px and below), lit by the kana in the result.

### Typed-Out Result
The result is not swapped in; it is typed. A paste, a swap, a layout change or Auto-detect types the result out grapheme by grapheme at about 20ms a character, speeding up so that no result takes longer than about 0.7s, with the accent caret visible while typing and the matching key struck per character. Typing a single character updates instantly. When the output is focused the caret blinks (1.05s, stepped). On Swap the two texts also slide past each other (input in from the right, output from the left, 24px over 0.5s), and the status counts drop into place (6px over 0.45s) whenever an animated update changes them.

### Footer Credit
A single mono line, "Made by Thanate Amornjiraporn (Focus)", in Credit type and muted ink, under a light rule at the page's full content width.

### Motion
All motion uses one ease-out curve (`cubic-bezier(0.16, 1, 0.3, 1)`).
- **Entrance:** on page load the intro, controls, panes, code table and notes rise 14px and fade in over 0.7s, 70ms apart, once.
- **Paper or mode change:** the new colours wipe in as a circle growing from the control that was used to the farthest corner (0.56s, a View Transition); where View Transitions are missing the change is instant.
- **Page change:** moving between the two tools is a cross-document View Transition: the header holds still and the ink-filled active tab glides to its new place (0.4s).
- **Floating surfaces:** the settings panel (0.26s) and a listbox (0.22s) pop in from 6px above at 97% scale, from their anchored corner; listbox options then drop in 4px one after another (0.3s, 15ms apart, capped at 105ms).
- **Auto-detect:** when it swaps the layouts both pickers flash an accent ring once (0.9s).
- **Small state:** the key strike (0.24s), heat fill changes (0.25s), the legend roll (0.5s), the swap slide (0.5s), the status tick (0.45s), the copy check draw (0.4s), the Copied slip (1.4s), chevrons (0.25s), the paper check (0.2s fade, 0.3s scale), the logo press (0.2s) and the Swap arrows (0.35s); buttons transition borders and fills in 0.15s and press in 0.1s.
- **Reduced motion:** under `prefers-reduced-motion: reduce` every animation and transition is cut to effectively zero, cross-page and theme View Transitions are skipped, and the result is shown at once instead of typed out.

### Named Rules
**The Shown Mechanism Rule.** Every converter surface pairs its result with a code table that shows, per key or cell, the source, the target and how often it was used.

**The Struck Key Rule.** Motion only ever answers the user: a keystroke, a conversion, a copy, a setting, a menu or a page change. The one exception is the single entrance when a page loads; nothing else moves on its own, nothing loops but the focused caret, and everything stops under reduced motion.

## Do's and Don'ts

### Do:
- **Do** take every colour from the eleven role variables so all five papers work unchanged in both modes.
- **Do** define a light and a dark token set for any new paper, and check its accent against its own keycap before adding `--heat-ink`.
- **Do** keep the accent for live state and the single primary action: used and struck keys, caret, focus, selection, the lead count, the chosen paper and layout, Copy.
- **Do** set codes, counts, labels and typed text in Martian Mono (uppercase 11px at 0.06em for labels) and add the `--script` stack wherever user or mapped text can appear.
- **Do** put the source legend top-left and the target bottom-right on every cap, and drive its tint from the heat ink by usage.
- **Do** build structure with 1px rules: strong ink for frames, light rules inside, dashed for gaps and cuts.
- **Do** keep new motion short, on the shared ease-out curve, tied to a user action, and switched off under reduced motion.
- **Do** draw icons as inline SVG with a 1.75 round stroke in `currentColor`.

### Don't:
- **Don't** use gradients, textures, or drop shadows on resting surfaces; the settings panel and an open listbox are the only shadows.
- **Don't** use red; the warning ink is burnt sienna in light mode (amber, or peach on Blueprint, in dark) and appears only on a non-zero miss count.
- **Don't** add a second accent or a second primary button to a page.
- **Don't** shrink the keyboard below legibility on a phone; split it into half-boards instead.
- **Don't** use icon fonts, emoji or text glyphs as interface icons.
- **Don't** couple paper and mode back into one theme list; they are two independent choices.
